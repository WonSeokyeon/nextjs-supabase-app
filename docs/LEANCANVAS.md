## 1. 문제 (Problem)

- 수영, 헬스, 친구 모임 등 정기 소모임에서 주최자가 **공지 / 참여자 관리 / 카풀 / 정산** 4가지 업무를 매번 반복 수행
- 이 업무들이 카카오톡 단체방, 엑셀, 개인 메모 등 **수작업**으로 처리되어 채팅방 대화 속에 정보가 흩어짐
- 참여자 입장에서도 공지·정산 정보를 놓치기 쉬움
- 특히 정산은 "누가 얼마를 냈는지"와 "누가 얼마를 내야 하는지"가 뒤섞여 불투명하게 관리됨

## 2. 고객 세그먼트 (Customer Segments)

| 역할               | 설명                                                                |
| ------------------ | ------------------------------------------------------------------- |
| 주최자 (owner)     | 클럽을 만들고 전체 운영. 클럽/이벤트/공지/정산 최종 관리 권한       |
| 운영진 (admin)     | 주최자가 위임한 보조 관리자. 이벤트/공지/멤버 관리 가능 (설정 제외) |
| 일반 멤버 (member) | 초대코드로 가입, RSVP, 카풀 신청, 정산 현황 열람                    |

가입은 초대코드로만 가능한 **비공개(폐쇄형) 모임** 전제 — 클럽 공개 탐색/검색은 MVP 비목표.

## 3. 가치 제안 (Unique Value Proposition)

> 모임 주최자가 클럽(정기 모임)과 회차(이벤트)를 만들어, 공지·참여자·카풀·정산을 **채팅방 없이 한 화면 흐름 안에서** 관리할 수 있다.

- 주최자: 클럽 생성부터 정산 마감까지 서비스 하나로 완결
- 참여자: 초대코드 가입 → RSVP → 카풀 신청 → 정산 확인까지 별도 안내 없이 직관적으로 수행

## 4. 해결책 (Solution)

1. **클럽 & 멤버십** — 클럽 생성, 초대코드 발급/재발급, 초대코드로 가입, 역할(owner/admin/member) 관리, 탈퇴/추방
2. **이벤트(회차) & 참여자 관리** — 클럽 아래 회차 생성, 정원 설정, RSVP(참석/불참/대기/미정), 정원 초과 시 대기 처리
3. **공지** — 클럽 단위 또는 특정 회차 단위 공지 작성, 상단 고정
4. **카풀** — 운전자가 좌석 제공(출발지/시간/좌석수) 등록, 참여자가 탑승 신청, 운전자가 승인/거절
5. **정산** — 회차별 비용 항목 등록, 참석자 기준 자동 분담 계산, 주최자가 입금 확인 체크

실제 결제(PG) 연동 없이 계산·기록까지만 처리하고, 송금은 카카오페이 등으로 참여자가 외부에서 직접 처리 (MVP 비목표).

## 5. 경쟁우위 (Unfair Advantage)

- **정산 분리 원칙**: `settlement_items`(누가 얼마를 냈는지)와 `settlement_shares`(누가 얼마를 내야 하는지 + 입금 확인 여부)를 분리 설계 → 계산과 확인 상태를 독립적으로 관리해 "카톡+엑셀" 조합보다 투명한 정산 제공
- **권한 원칙**이 명확함: 조회는 전체 멤버, 대부분의 쓰기는 owner/admin, 본인 관련 행위(RSVP·카풀 신청)는 본인만 — 소규모 모임 운영에 맞춘 권한 설계
- `[추정]` 카톡방 기반의 기존 방식 대비 전환 비용(러닝커브)이 낮은 UX가 확보된다면 후발주자 대비 우위로 작용할 수 있음
